# 管理员全局补卡设计

## 背景

普通成员已经有“补昨天打卡”的能力，这条路径保持不变。管理员需要一个独立入口，可以给团队任意成员补当前月份内的漏卡日期，用于处理忘点、误操作或线下确认过的训练记录。

## 规则

- 只有 `ADMIN` 用户可以使用管理员补卡。
- 管理员可以给同队任意成员补卡。
- 只能补当前月份、今天之前的日期。
- 目标用户在该日期已经有打卡记录时拒绝补卡。
- 管理员补卡不限次数。
- 管理员补卡固定奖励 `+10 银子`。
- 管理员补卡计入赛季格子和赛季收入。
- 管理员补卡不发健身券、不发 EXP、不结算 boost、不触发连签阶梯奖励。
- 普通成员的“只能补昨天”入口和 API 保持原行为。

## 数据记录

新增管理员补卡流水，记录管理员、目标用户、团队、日期、奖励和关联的 `PunchRecord`。`PunchRecord.punchType` 使用 `admin-makeup`，用于区分普通打卡和昨天补签。

## UI

在健身打卡热力图里，管理员可以直接点击任意队员本月过去的漏卡格补卡；确认弹窗说明固定 `+10 银子` 且不补健身券、EXP、boost 或连签阶梯奖励。普通成员仍然只看到自己昨天的补卡入口。

现有 `/admin` 管理中心保留“全局补卡”模块，作为已知队员和日期时的精确输入兜底。模块复用现有管理页的 `soft-card`、表单、状态提示和按钮样式。

## 验证

- API 测试覆盖管理员成功补卡、非管理员拒绝、重复日期拒绝、跨成员拒绝。
- 组件测试覆盖管理页模块可达、表单提交新 API、成功/错误状态展示，以及管理员从热力图漏卡格直接补卡。
