# 今日训练小票可编辑设计

## 背景

当前分支已经把“今日训练小票”从静态原型推进到真实打卡路径：第一次点击今日 `+` 时，前端提交训练类型、有氧项目、力量部位和训练时长，后端创建当天唯一的 `PunchRecord`，并创建一对一的 `WorkoutRecord` 和多条 `WorkoutEntry`。

用户的新需求是：第一次打卡后，如果当天晚上又练了新的部位，应该能像喝水/咖啡继续调整当天记录一样，重新打开今天的小票编辑训练内容。这个编辑能力必须服务后续统计，例如过去一个月练胸 10 次、腹 5 次。

## 目标

- 今天未打卡时，点击当前用户今日 `+` 仍然打开训练小票并完成打卡。
- 今天已打卡时，点击当前用户今日 `✓` 打开已填好的训练小票。
- 保存已打卡后的训练小票时，只更新当天 `WorkoutRecord` 和 `WorkoutEntry`。
- 保存编辑不创建第二条 `PunchRecord`，不重复发健身券，不改变银子、连签、赛季进度、EXP、boost 结算。
- 撤销打卡仍然可用，但从已打卡小票里作为次要危险操作触发。
- API 返回的 `BoardSnapshot` 带上当前用户今天的训练小票数据，供 UI 预填。
- 旧数据继续统一视为有氧跑步机、无力量；既有 backfill 机制保持这个口径。

## 数据模型

继续使用现有三层模型：

- `PunchRecord`：一日唯一，代表“今天是否完成健身打卡”。
- `WorkoutRecord`：一张训练小票，和 `PunchRecord` 一对一。
- `WorkoutEntry`：训练明细，一条代表一个统计维度。

示例：

- 跑步机：`category = "cardio"`, `code = "treadmill"`
- 胸：`category = "strength"`, `code = "chest"`
- 腹：`category = "strength"`, `code = "abs"`

编辑当天训练时，后端替换该 `WorkoutRecord` 下的 `WorkoutEntry` 集合。统计按 `WorkoutEntry` 聚合，因此同一天勾选胸和腹，会让胸 +1、腹 +1，但当天训练天数仍然只算 1 天。

## API 设计

复用现有 `/api/board/punch` 路由：

- `POST /api/board/punch`：未打卡时创建今日打卡和训练小票。
- `PATCH /api/board/punch`：已打卡时更新今日训练小票。
- `DELETE /api/board/punch`：撤销今日打卡，保持现有行为。

`PATCH` 请求体和 `POST` 一致：

```json
{
  "trainingType": "both",
  "cardioItem": "treadmill",
  "strengthParts": ["chest", "abs"],
  "durationMinutes": 60
}
```

`PATCH` 返回：

- `200`：返回最新 `BoardSnapshot`。
- `400`：训练小票 payload 不合法，返回 `invalid-workout-payload`。
- `401`：未登录或用户不存在。
- `404`：今天还没有打卡，返回 `today-punch-not-found`。
- `500`：不可预期服务端错误。

## 快照设计

`BoardSnapshot` 新增：

```ts
currentUserTodayWorkout?: WorkoutTicketPayload | null;
```

含义：

- 当前用户今天已打卡且有训练小票：返回可直接预填 UI 的 `WorkoutTicketPayload`。
- 当前用户今天未打卡：返回 `null`。
- 当前用户今天已打卡但缺少旧小票：返回 `null`，UI 使用默认小票，保存后补齐 `WorkoutRecord`。

`durationMinutes` 在 UI 编辑态使用数字。旧数据里未知时长为 `null`，转换给 UI 时使用默认 60 分钟。

## 前端交互

未打卡：

1. 当前用户今日格子显示 `+`。
2. 点击后打开“今日训练小票”。
3. 主按钮文案为“确认打卡”。
4. 成功后格子变 `✓`，发放 1 张健身券。

已打卡：

1. 当前用户今日格子显示 `✓`。
2. 点击后打开“今日训练小票”，预填当前训练内容。
3. 主按钮文案为“保存修改”。
4. 保存成功后只更新训练明细，日志提示“已更新今日训练小票”。
5. 小票内提供“撤销打卡”次要危险操作，触发现有撤销流程。

## 错误处理

- 保存编辑失败时，小票保持打开，并在小票内展示错误。
- 保存编辑时按钮进入 busy 状态，防止重复提交。
- 撤销失败时，小票保持打开，并展示撤销错误。
- 请求体校验仍然由 `parseWorkoutTicketPayload()` 统一处理。

## 非目标

- 不新增多次训练记录模型。
- 不做按小时记录训练段。
- 不给每个力量部位单独填写时长。
- 不改变补签、管理员补卡的默认历史 workout 口径。
- 不在本次新增月度统计 UI；本次只保证数据结构可统计。

## 人工验收

正常情况：

- 未打卡时点击今日 `+`，选择跑步机、胸、腹并确认，今日格子变 `✓`。
- 已打卡后点击今日 `✓`，小票打开并保留刚才选择的项目。
- 再勾选肩并保存，刷新页面后再次打开，胸、肩、腹都仍然被选中。
- 保存编辑后健身券余额不再 +1，银子、连签、赛季进度不变化。
- 在已打卡小票中点击“撤销打卡”，今日格子恢复可打卡状态。

需要调查的问题：

- 点击 `+` 或 `✓` 后小票不出现。
- 保存编辑返回 `server-error`。
- 保存编辑后健身券、银子或连签发生变化。
- 刷新后训练明细丢失。
- 同一天出现多条 `PunchRecord`。
