# Home UI Scene Refresh Design

> 将主页各 tab 从统一基础卡片升级为同一产品家族下的分页面小场景。第一轮只做 UI、布局、动效和媒体资源，不改变任何数据、接口、业务规则或状态语义。

## 背景

主页当前是 `app/(board)/page.tsx` 内的单页 tab stage，包含：

- `punch`: 健身打卡
- `board`: 共享看板
- `coffee`: 续命咖啡
- `calendar`: 牛马日历
- `dash`: 战报中心
- `supply`: 牛马补给站

用户认可“牛马补给站”的游戏化视觉方向，希望把其他主页 tab 逐步调整为风格一致的小场景。已确认的总体方向是 **分页面小场景**：共享同一套 brutalist 产品语言，但每页有自己的场景隐喻。

## 总目标

1. 让主页各 tab 看起来属于同一个产品家族。
2. 保留当前高频工具属性，不做营销页或纯装饰页面。
3. 每个页面只围绕已有组件和已有数据做视觉升级。
4. 支持逐页实现和逐页验收，避免一次性重写主页。
5. 建立后续媒体资源、动效和 reduced motion 的约束。

## 严格非目标

- 不改 Prisma schema。
- 不改 API contract。
- 不改状态管理、reducer action 或数据流。
- 不新增业务功能。
- 不新增新的统计口径。
- 不新增不存在的按钮、筛选器、详情页、弹窗或管理能力。
- 不重命名 tab key。
- 不改变认证逻辑。
- 不改变打卡、咖啡、日历、战报、补给站的业务规则。

## 共享视觉底座

### 导航

桌面导航保持现有 6 个 tab，顺序统一为：

```text
健身打卡 / 共享看板 / 续命咖啡 / 牛马日历 / 战报中心 / 牛马补给站
```

右侧保留：

- 通知铃铛 `TeamDynamicsBell`
- 当前用户 profile/avatar 按钮

导航可优化外观，但不改变 tab 切换行为。

### Tab Stage

建立共享的页面场景容器语法：

- 全页保留浅色 dotted 或纸面背景。
- 每个 tab 内部有自己的 scene shell。
- 页面切换可使用 opacity + transform 的轻量转场。
- 不使用大面积暗色大屏、玻璃拟态、紫蓝渐变或营销 hero。

### 媒体资源

新增 PNG/GIF/视频资源时应放在 `public/assets/<feature>/` 下，例如：

- `public/assets/home-scenes/punch/`
- `public/assets/home-scenes/board/`
- `public/assets/home-scenes/coffee/`
- `public/assets/home-scenes/calendar/`
- `public/assets/home-scenes/report/`

资源只做装饰或现有信息的视觉表达，不承载业务逻辑。

### 动效

允许：

- 页面进入的轻量 stagger。
- 今日格子、主按钮、便签 hover、咖啡杯数变化的短反馈。
- 成功反馈的 1-2 秒短暂浮层。
- 背景装饰的极低频微动。

禁止：

- 长时间循环抢焦点动效。
- 会影响表格/格子可读性的动效。
- 通过动效表达不存在的新业务状态。

必须支持 `prefers-reduced-motion: reduce`，关闭非必要动效。

## 页面设计

### 健身打卡

视觉隐喻：**健身房打卡墙**。

真实模块：

- `Navbar`
- `TeamHeader`
- `HeatmapGrid`
- `ActivityStream`

允许优化：

- 外层 gym wall 场景背景。
- 顶部金库/赛季/个人摘要卡片的粗描边和 gym notice-board 质感。
- 今日列、当前用户头像、当前用户今日格子的视觉强调。
- 打卡成功后的短暂浮层反馈。
- 活动动态改成更像实时 ticker/训练日志。

禁止新增：

- 独立今日完成率卡片。
- 今日未打卡成员列表。
- 排行榜、战力条、任务面板、额外奖励面板。
- 重复展示今日打卡人数。

### 共享看板

视觉隐喻：**办公室便签墙**。

真实模块：

- `SyncStatus`
- `NoteComposer`
- `BoardMessage`
- `NoteMasonry`
- `NoteCard`

允许优化：

- 便签墙/纸面/胶带/图钉/回形针背景。
- 发布区像正在书写的便签夹板。
- 颜色 swatch 更明确。
- 团队通告和自由笔记的层级更清楚。
- 便签 hover、发布成功、删除中的微反馈。

禁止新增：

- 评论、点赞、反应。
- 频道、未读数、成员在线列表。
- 置顶交互或管理区。
- 任务、日程、排行榜。

### 续命咖啡

视觉隐喻：**咖啡小票台**。

真实模块：

- `CoffeeReceipt`
- `CoffeeGrid`
- `CoffeeActivityFeed`
- 今日杯数调整 dialog

允许优化：

- 小票纸、收银台、杯套、蒸汽线、咖啡杯贴纸。
- 左侧小票区强化“今日咖啡小票”。
- `+1 杯` 作为主操作，`-1 杯` 作为次操作。
- 右侧团队续命月历保持主要数据墙。
- 咖啡动态保持日志形态。

禁止新增：

- 咖啡菜单、价格、订单、饮品种类。
- 咖啡因健康评分。
- 咖啡排行榜之外的新榜单。
- 奖励、积分、成就或任务。

### 牛马日历

视觉隐喻：**桌面月历 / 个人记录册**。

真实模块：

- `CalendarHeader`
- summary chips
- `CalendarGrid`
- `CalendarDayCell`

允许优化：

- 大纸质月历、夹子、标签纸、高亮笔、咖啡 stamp。
- `上个月` / `回到本月` 按钮更贴合 brutalist 语言。
- 今日格子强调。
- `练` 和咖啡图标的图形层级更清楚。

禁止新增：

- 成员排班视图。
- 日程、提醒、待办。
- 日详情抽屉。
- 视图切换、筛选器。
- streak、预测、团队统计。

### 战报中心

视觉隐喻：**月度战报编辑台**。

真实模块：

- `ReportHeader`
- `Milestones`
- `TrendChart`
- `CoffeeReportPanel`
- `GamificationWeeklyReportPanel`
- `WeeklyReportAdminPanel`，仅管理员可见

允许优化：

- 报纸版面、剪报、夹子、批注标签、图表贴纸。
- 顶部战报头更像正式月报。
- 四个指标卡视觉层级更稳定。
- 活跃趋势图作为主要分析区。
- 咖啡能量站保留小票/杯子视觉。
- 牛马补给周报像附刊卡片。

禁止新增：

- 日期范围选择。
- 导出 PDF、AI 总结、筛选器。
- 成员画像、预测、目标管理。
- 新指标卡。
- BI 大屏式暗色仪表盘。

## 实现顺序

建议按以下顺序逐页实现：

1. 共享视觉底座最小集 + 健身打卡样板页。
2. 共享看板。
3. 续命咖啡。
4. 牛马日历。
5. 战报中心。
6. 统一 polish：移动端、reduced motion、资源压缩、跨页一致性。

每一步都应能独立验收并可单独回退。

## 验收标准

- 桌面端每个 tab 与设计方向一致。
- 移动端不遮挡、不溢出、不丢失核心操作。
- 所有页面仍使用现有数据和现有接口。
- 页面中不出现当前代码没有的数据模块。
- 动效可通过 `prefers-reduced-motion` 降级。
- `npm test` 和 `npm run lint` 通过。
- 如改动明显涉及布局，需用浏览器检查桌面与移动宽度。

## 测试策略

第一轮以 CSS/组件行为和视觉结构风险为主：

- 保留现有组件测试。
- 对新增 scene shell class、关键按钮和状态文案加轻量测试。
- 对不应出现的额外模块保持代码审查约束，不通过测试硬编码大量视觉细节。
- 每页实现后启动本地开发服务器，用浏览器检查桌面和移动视口。

## 设计确认状态

已确认的方向：

- 全局：分页面小场景。
- 健身打卡：健身房打卡墙。
- 共享看板：办公室便签墙。
- 续命咖啡：咖啡小票台。
- 牛马日历：桌面月历 / 个人记录册。
- 战报中心：月度战报编辑台。

后续实现前仍需要逐页确认具体代码计划。
