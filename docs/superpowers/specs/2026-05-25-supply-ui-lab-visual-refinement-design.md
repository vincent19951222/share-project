## Context

当前 `/ui-lab/supply-dashboard` 页面族已经具备明确的像素游戏 + 健身补给站 + brutalist 粗边框风格。整体方向成立，记忆点强，尤其是 Dashboard 主视觉、补给商店、抽卡机和背包库存这几类页面已经不像通用后台模板。

当前主要问题不是“缺少风格”，而是风格密度过高：顶部栏、资源胶囊、侧栏、任务卡、商品卡、详情卡、按钮和公告都使用高对比、粗边框、厚阴影和重字重，导致视觉层级被压平。用户进入页面后很容易感到热闹，但不一定能立刻判断当前最重要的动作是什么。

本专项目标是把 UI Lab 从“复刻得像”推进到“作为产品原型也好用”：保留强识别度，同时降低噪音、统一素材语言、强化主流程焦点，并让移动端不丢失核心品牌记忆点。

## Goals

1. 建立页面族统一的视觉层级规则，明确哪些元素可以最高对比，哪些元素必须后退。
2. 统一 3D/插画、像素图标、brutalist 面板之间的资产处理方式，减少拼贴感。
3. 优化顶部栏和资源区的信息密度，特别是移动端的可读性和可操作性。
4. 保留 Dashboard 主视觉作为页面族第一记忆点，并提供移动端压缩形态。
5. 强化关键交互的游戏化反馈：完成任务、兑换商品、使用道具、抽奖、领取奖励。
6. 按页面定义可执行的视觉优化项和验收标准，方便后续分批实现。

## Non-Goals

- 不接入 Prisma、API Routes、真实登录用户、真实库存、真实抽奖、真实兑换或真实任务记录。
- 不替换生产 `components/gamification/SupplyStation.tsx`。
- 不新增生产导航入口。
- 不重做信息架构，不改变已有 UI Lab route 范围。
- 不追求逐像素复刻原型图；可读性、主次层级和响应式体验优先。
- 不引入外部 UI 组件库。

## Design Direction

### Purpose

牛马补给站是健身团队的游戏化补给大厅。它要让用户快速知道：

- 今天自己的状态如何。
- 今天还有哪些主线任务。
- 可以用银子或抽奖券做什么。
- 背包里有什么道具，以及什么时候用。
- 历史奖励、兑换和队友互动发生了什么。

### Tone

保留当前方向：像素游戏 UI + 健身房补给站 + brutalist 粗边框。

优化后的关键词：

- 强记忆点，而不是全屏都吵。
- 游戏感，而不是后台表格感。
- 高对比但有层级。
- 素材混搭但有统一处理。
- 中文可读，而不是只服务截图效果。

### Differentiation

页面最应该被记住的是“健身牛马站在补给大厅里，今天要完成任务、攒银子、抽补给、用道具”。因此 Dashboard 主角色、任务卡、抽卡机和背包道具应成为核心视觉资产。其它面板只是服务这些主流程，不应该抢主角。

## Global Visual Principles

### 1. 对比度分层

页面元素按 4 个视觉强度等级处理：

#### Level 1: 主焦点

允许使用最高对比、厚边框、强阴影、高饱和黄色或橙色。

适用对象：

- Dashboard 主角色和等级条。
- 今日主线任务卡当前未完成状态。
- 抽卡机主按钮。
- 商店当前选中商品和兑换按钮。
- 背包当前选中道具和使用按钮。

#### Level 2: 次焦点

保留粗边框，但减少阴影和饱和度。

适用对象：

- 状态面板。
- 商品详情。
- 背包详情。
- 任务记录主时间线。
- 抽卡池概率、保底和规则卡。

#### Level 3: 辅助信息

使用浅底、细边框、少阴影或无阴影。

适用对象：

- 说明文案。
- 状态解释。
- 限购、来源、使用时机等属性行。
- 筛选、排序、日期 tabs。

#### Level 4: 背景与装饰

只提供氛围，不抢主流程。

适用对象：

- 背景图遮罩。
- 半调纹理。
- 小贴纸、小角标、低频装饰。

### 2. 边框和阴影节制

当前页面族大量使用 4px border + 7px/8px shadow。优化后应按层级收敛：

- 主焦点：4px border + 6px shadow。
- 次焦点：3px border + 3px shadow。
- 辅助信息：2px border，无 shadow 或 1px inset。
- 同一屏内最多 2 个区域使用最重阴影。

### 3. 黄色使用规则

黄色是品牌和主 CTA 色，不应成为所有容器的默认底色。

允许高饱和黄色的场景：

- 当前页面导航态。
- 主行动按钮。
- Dashboard 首页入口。
- 重要奖励、进度或完成状态。

需要降级的场景：

- 普通说明卡。
- 非选中筛选项。
- 侧栏默认项。
- 重复出现的资源胶囊背景。

### 4. 字重与字号

当前大量 `font-weight: 1000` 带来游戏感，但也削弱层级。建议：

- 页面标题、关键数字、主 CTA：900-1000。
- 卡片标题、任务名、商品名：800-900。
- 属性标签、说明文案、限制文案：650-750。
- 长段中文避免超重字重，优先保证可读性。

### 5. 资产统一处理

当前素材包含精致 3D/插画、像素道具、图标按钮和 CSS 面板。允许混搭，但需要统一外观处理：

- 大角色图可以保留插画质感，但加统一投影和描边规则。
- 道具图标统一使用透明底、像素化或硬边阴影。
- 任务卡插画统一套用同一张卡框、稀有度色和完成贴纸。
- 不再直接裁整块面板图片作为 UI。
- 所有图片都要有稳定尺寸，避免加载后挤压布局。

### 6. 文案降噪

避免同屏重复解释用户已经能看到的内容。属性信息尽量短：

- `效果`：一句话说明。
- `使用时机`：短标签。
- `购买限制`：短标签。
- `来源`：短标签。

说明性长文只放在可展开规则区或页面底部。

## Shared Component Requirements

### Topbar

桌面端：

- 品牌、导航、资源和头像继续保留在同一顶部栏。
- 当前页面 tab 是唯一允许使用重边框 + 高亮底色的导航项。
- 非当前 tab 降低背景对比，避免像按钮组一样抢注意力。
- 资源胶囊减少厚阴影，优先突出数值和图标。

移动端：

- 第一行显示品牌、当前页、头像或关闭按钮。
- 第二行显示页面 tabs。
- 第三行显示资源胶囊，可横向滚动或紧凑网格。
- 资源项隐藏文字标签时必须保留可访问标签。
- 不允许资源数值被截断到不可理解。

### Pixel Panel

`SupplyUiLabPixelPanel` 应支持视觉层级 tone，而不是所有面板同强度：

- `hero`：主焦点。
- `primary`：次焦点。
- `paper`：普通信息。
- `quiet`：辅助信息。
- `dark`：深色强调。

### Action Button

按钮需要明确主次：

- 每屏最多一个主 CTA。
- 次要动作使用浅底或 ghost。
- 危险/消耗型动作需要明确成本提示。
- disabled 不只变灰，还要解释原因。

### Status Badge

状态徽章按语义统一：

- 成功：绿色。
- 警告/待确认：黄色或橙色。
- 稀有/SSR：金色或紫色，但不要和警告混淆。
- 过期/不可用：低饱和灰。

### Feedback

关键动作必须有即时反馈：

- 点击任务卡：出现确认或完成贴纸。
- 完成任务：任务卡盖章、进度点亮、奖励区变化。
- 商品兑换：按钮进入已兑换/待管理员确认/余额不足状态。
- 背包使用：详情区显示本地结果。
- 抽卡：券余额变化、结果区出现、稀有度有明显区分。

## Page Requirements

### Dashboard

当前优势：

- 主角色和健身房背景是页面族最强记忆点。
- 今日主线和快捷入口让游戏大厅结构清晰。
- 任务卡已经比普通列表更有玩法感。

问题：

- 左右面板和底部快捷入口同样厚重，削弱了中间角色。
- 移动端隐藏 hero 后，页面失去品牌记忆点。
- 任务完成态还不够像游戏反馈。

优化要求：

1. 中间角色区保持最高视觉优先级，左右面板降一级。
2. 状态面板减少阴影厚度，今日效果行改成更轻的属性列表。
3. 任务完成态使用盖章、贴纸、勾选徽章或卡片压暗，而不是普通遮罩。
4. 底部快捷入口只让当前主入口使用强黄色，其它入口使用浅色卡。
5. 移动端增加压缩版 hero：角色小图、Lv、经验条、今日一句话。
6. 公告栏降低高度和颜色强度，避免像主 CTA。

验收标准：

- 桌面首屏一眼能看出主视觉、今日任务、主 CTA 三个层级。
- 移动端首屏仍能看到牛马角色或明确品牌视觉。
- 完成一个任务后，用户不读提示文案也能看出状态变化。

### Shop

当前优势：

- 三栏结构完整：分类、商品网格、详情。
- 商品卡有价格、限制、稀有度和图标。
- 当前选中商品有详情承接。

问题：

- 商品卡之间视觉权重太平均，选中态不够突出。
- 详情面板信息多，但不像游戏道具属性面板。
- 左侧分类和商品卡都很重，主流程焦点分散。

优化要求：

1. 当前选中商品在 grid 中增加明确选中轮廓、角标或轻微位移。
2. 商品详情改成道具属性面板结构：名称、稀有度、持有、效果、时机、限制、花费。
3. 分类侧栏默认项降噪，只让 active 分类使用高亮。
4. 商品卡价格区统一对齐，避免不同文案长度导致视觉跳动。
5. 兑换按钮根据 mock 状态展示：可兑换、余额不足、今日已达上限、需管理员确认。
6. 规则说明默认收起，避免和商品网格抢屏幕。

验收标准：

- 用户能在 2 秒内识别“当前选中商品”和“能否兑换”。
- 商品卡列表可扫读，不需要每张卡都像主 CTA。
- 详情栏不重复商品卡已经足够明显的信息。

### Task Record

当前优势：

- 侧栏模式、日期 tabs、筛选和时间线结构完整。
- 记录类型覆盖任务、奖励、抽奖、兑换和队友互动。

问题：

- 筛选、日期、菜单、徽章较多，主时间线不够突出。
- 不同事件类型的视觉区分可以更固定。

优化要求：

1. 强化时间线主轴，记录卡片降噪，时间、类型和奖励形成固定节奏。
2. 不同事件类型使用固定色和小图标：
   - 任务完成：绿色。
   - 奖励领取：黄色。
   - 抽奖：粉/紫。
   - 兑换：橙色。
   - 队友互动：蓝色。
3. 日期 tabs 降低视觉强度，只突出当前日期。
4. 侧栏 badge 只用于需要处理的数量，不用于装饰。
5. 空状态需要说明当前筛选下没有记录，并给出返回“全部”的动作。

验收标准：

- 不看正文也能从颜色和图标识别记录类型。
- 当前筛选和当前日期明确。
- 时间线是页面主角，不被侧栏和筛选条压过。

### Backpack

当前优势：

- 背包天然适合游戏库存网格。
- 分类、库存、详情三块清晰。
- 今日效果可以和道具使用形成闭环。

问题：

- 详情区还可以更像“物品鉴定卡”。
- 可用/不可用、可使用/待确认的状态需要更直观。

优化要求：

1. 库存格按稀有度提供边框和角标，但默认空格保持安静。
2. 当前选中道具有明显高亮，不依赖细微边框变化。
3. 详情区采用物品卡结构：大图、名称、稀有度、数量、效果、使用时机、结果预览。
4. 使用按钮根据状态展示：立即使用、今天已生效、需管理员确认、不可使用。
5. 今日效果卡降低密度，只保留生效中的关键效果；详细来源可展开。
6. 移动端优先展示库存和详情，分类可以变成横向 tabs。

验收标准：

- 用户能快速判断道具是否可用、用后发生什么。
- 背包网格稳定，不因名称或数量改变而跳动。
- 空格不会比真实道具更抢眼。

### Draw Pool

当前优势：

- 抽卡机具备强视觉焦点，是页面族最有表现力的二级页。
- 钱包、概率、保底、规则、结果区结构完整。

问题：

- 单抽/十连 CTA 还可以更像机器控制区。
- 抽奖结果的稀有度层级需要更明显。
- 规则和概率信息不应压过抽卡机本体。

优化要求：

1. 抽卡机和抽卡按钮保持页面最高焦点。
2. 十连按钮视觉权重大于单抽，但成本和券不足状态必须清楚。
3. 抽卡按钮可采用机器控制杆、插券口或街机按钮的视觉隐喻。
4. 结果区按稀有度分层展示：
   - SSR：金色框、独立强调、强反馈。
   - SR：较强边框和色彩。
   - R/N：轻量列表或普通卡。
5. 概率、保底、规则默认作为辅助 rail，必要时可折叠。
6. 券余额不足时，不只 disabled，还要显示还差几张和获取入口。

验收标准：

- 用户一眼知道要点击哪里抽卡。
- 十连、单抽和券不足状态明确。
- 抽到高稀有度时，视觉反馈明显区别于普通掉落。

## Responsive Requirements

### Desktop

- 保持游戏大厅式舞台布局。
- 主视觉和主流程卡片不能被侧栏等高强度元素压过。
- 页面固定比例可以保留，但不应造成关键信息在常见桌面高度下被裁切。

### Tablet

- 允许两栏布局。
- Topbar 分行显示，资源区可横向滚动。
- 详情面板可以移到列表下方，但选中关系必须清楚。

### Mobile

- 页面不只是缩小桌面版。
- Dashboard 不隐藏品牌主视觉；使用压缩 hero。
- 商店、背包、任务记录优先展示当前任务区域，侧栏改横向 tabs 或折叠。
- 抽卡页优先展示抽卡机、券余额和主按钮；规则概率后置。
- 所有按钮文字必须完整可读，不使用依赖 hover 的关键信息。

## Accessibility Requirements

- 所有按钮、tabs、商品卡、道具格、任务卡必须有明确 `aria-label` 或可见文本。
- 选中态使用 `aria-selected`、`aria-current` 或 `aria-pressed`，不要只靠颜色。
- 进度条使用 `role="progressbar"` 并提供当前值。
- 颜色不能是唯一状态表达；完成、过期、余额不足、需确认都需要文字或图标。
- 焦点态要可见，并且符合像素风但不能被阴影掩盖。
- reduced motion 下禁用非必要动画。

## Motion Guidelines

本专项只定义轻量 motion，不做复杂动画系统：

- 页面进入：核心面板可使用短暂 stagger reveal。
- 按钮按下：使用 `transform: translate(2px, 2px)` 和 shadow 收缩。
- 任务完成：贴纸/盖章出现，进度点亮。
- 抽卡结果：结果卡从机器下方或结果区轻微弹入。
- 不使用 bounce/elastic；使用自然减速。
- 不动画布局尺寸，优先使用 opacity 和 transform。

## Implementation Priority

### P0: 层级降噪

- 为 panel、button、badge 增加视觉层级 tone。
- 调整 Dashboard 左右面板、快捷入口、公告栏权重。
- 调整 Topbar 非当前 tab 和资源胶囊权重。

### P1: 移动端核心体验

- Dashboard 增加移动端压缩 hero。
- Topbar 移动端三行结构稳定。
- 商店、背包、任务记录移动端从侧栏改横向 tabs 或自然堆叠。

### P2: 页面主流程反馈

- Dashboard 任务完成贴纸。
- Shop 兑换状态。
- Backpack 使用结果预览。
- Draw Pool 抽奖结果稀有度层级。
- Task Record 类型色和空状态。

### P3: 资产统一

- 梳理角色、道具、任务卡插画的统一描边、阴影和尺寸规则。
- 替换风格明显不一致的临时图。
- 输出视觉 QA 截图并更新对比基线。

## Visual QA Checklist

每次专项改动后至少检查：

检查项：

- 首屏主焦点是否明确。
- 顶部栏是否溢出或截断关键数值。
- 按钮文字是否完整可读。
- 卡片和面板是否出现文本重叠。
- 移动端是否保留页面核心记忆点。
- 完成、选中、禁用、余额不足等状态是否不只靠颜色表达。
- 页面是否仍符合牛马补给站的像素游戏气质。

## Acceptance Criteria

1. 页面族保留当前强风格，但同屏最高视觉强度元素数量明显减少。
2. Dashboard 桌面端主角色和今日主线成为首屏最明确焦点。
3. Dashboard 移动端不再完全丢失主角色/品牌视觉。
4. Shop 用户能明确识别当前选中商品、兑换成本和兑换状态。
5. Task Record 时间线类型可通过固定图标/颜色快速区分。
6. Backpack 用户能明确判断选中道具是否可用、使用后有什么结果。
7. Draw Pool 用户一眼能识别抽卡主按钮、券余额和结果稀有度。
8. Topbar 在桌面和移动端都不截断关键资源数值。
9. 视觉 QA 截图覆盖桌面和移动端关键页面。
10. 不影响生产补给站，不新增真实业务 mutation。
