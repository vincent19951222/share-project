# 移动端专属适配设计

## 背景

当前应用已经从简单打卡看板发展成多个强视觉页面：健身打卡、共享看板、牛马水铺、牛马日历、战报中心、牛马补给站、团队动态和文档中心。桌面端展示承担了主要视觉风格，不能因为移动端修复而被重排、降级或改色。

本轮目标是把移动端做到可用、顺滑、没有横向溢出，并且严格把影响限制在手机断点。已有部分移动端修复分散在 `app/globals.css` 多个 `@media` 块里；本轮不做桌面重设计，而是建立一层清晰的移动端覆盖规则和验收守卫。

## 目标

- 手机宽度 `360px` 到 `430px` 下，核心页面都能自然纵向浏览，不出现页面级横向滚动。
- 桌面宽度 `761px` 及以上展示保持不变；允许给组件补充 class hook，但不允许给桌面新增布局、尺寸、颜色或视觉层级变化。
- 导航、头像、动态铃铛、补给站资产、关键操作按钮的触控区域不小于 `44px`。
- 健身打卡、共享看板、水铺、日历、战报、补给站在手机上优先呈现主要任务，不让装饰素材、宽表格或桌面舞台挤压内容。
- 团队动态、文档中心这类长页在手机上可读、可筛选、可滚动，不要求重新设计信息架构。
- 用 CSS 单测和浏览器视觉验收双重确认移动端改动有效，同时用变更范围检查确认 PC UI 没被改动。

## 非目标

- 不修改任何 API、Prisma schema、业务状态或产品机制。
- 不重做 PC 端视觉，不改变 PC 端默认网格、间距、阴影、背景图或组件顺序。
- 不引入新的 UI 库、状态管理库或路由结构。
- 不把所有后台管理页面做成完整移动后台；只保证已有内容不溢出、基础操作可点。
- 不删除已有补给站 4 维任务、抽奖、背包、商店等能力。

## 断点约定

- 手机：`@media (max-width: 760px)` 为主断点。
- 补给站 UI Lab 既有测试使用 `@media (max-width: 768px)`，本轮保留并补齐该断点，避免破坏已有测试。
- 桌面：`min-width: 761px` 及以上视为 PC 展示范围。实现时默认样式必须继续表达桌面，移动端只通过媒体查询覆盖。
- 验收视口：`375x812`、`393x852`、`430x932`，并额外抽查 `1440x900` 桌面。

## 设计原则

### 移动端覆盖层

在 `app/globals.css` 末尾新增一组命名清晰的移动端覆盖规则，例如以注释 `/* Mobile-only adaptation layer */` 开始。新增布局修复优先放进这层，而不是继续散落在多个历史 `@media` 块中。这样后续 diff 能清楚看到哪些规则只服务手机。

默认规则和已有 PC 规则不改。确实需要给 JSX 增加 class hook 时，只添加 class 字符串，不改变 DOM 顺序、文本、按钮行为或数据流。

### 页面壳

根布局当前使用 `h-screen w-screen p-4 gap-4`。手机上这类固定视口容易造成滚动嵌套和横向挤压。本轮在手机断点内把 `body` 和 `board-tab-stage` 调整为纵向流式页面：保留导航在上，内容区独立滚动，但不让页面宽度超过视口。

### 导航

手机导航应保持两行以内：第一行是品牌和操作按钮，第二行是补给站资产摘要。移动菜单打开时纵向展示主 tab；补给站二级导航允许横向轻扫，但不能让整页横向滚动。桌面 tab strip、资产 chip、hover flyout 维持原样。

### 核心场景

健身打卡和共享看板保留“牛马”视觉语气，但手机上要降低装饰素材优先级。健身页以队伍状态、当前用户操作、热力图和动态流为顺序；共享看板以发布框和便签流为顺序。

牛马水铺的饮品卡片在手机上使用单列或双列，团队喝水表可以保留内部横向滚动，但滚动必须限制在表格容器内。

牛马日历和战报中心当前是桌面场景化视觉。手机上保留纸面和战报语气，但减少外圈装饰，保证标题、核心指标、月历网格、趋势和周报模块先读得到。

牛马补给站的 UI Lab 场景含有多个大舞台和最小宽度规则。手机上生产嵌入态优先任务流、资产、快捷入口和关键操作；商店、任务记录、背包、抽奖池都必须把 `min-width` 收回到容器内部或改为单列。

### 长页

团队动态筛选按钮、文档中心 tab 和目录在手机上需要可横向或纵向滚动，按钮高度满足触控要求。文档正文保持可读行宽，避免因为 sticky sidebar 或宽表格造成溢出。

## 测试策略

- 新增 `__tests__/mobile-only-adaptation-css.test.ts`，专门检查手机断点内的页面壳、导航、核心场景和长页规则。
- 复用并扩展现有测试：
  - `__tests__/navbar-supply-chrome.test.tsx`
  - `__tests__/home-ui-calendar-scene-css.test.ts`
  - `__tests__/home-ui-report-scene-css.test.ts`
  - `__tests__/supply-ui-lab-mobile-css.test.ts`
  - `__tests__/drink-checkin.test.tsx`
- CSS 测试只锁定移动端契约，不要求完整视觉快照，避免让测试阻碍后续微调。
- 每个任务完成后运行对应单测；最终运行 `npm run lint`、`npm run build`，并做浏览器视觉验收。

## 浏览器验收

在开发服务器中检查以下路由：

- `/`
- `/board`
- `/drink`
- `/calendar`
- `/report`
- `/dashboard/status`
- `/dashboard/shop`
- `/dashboard/task-record`
- `/dashboard/backpack`
- `/dashboard/draw-pool`
- `/dynamics`
- `/docs`

手机视口验收：

- `document.documentElement.scrollWidth <= window.innerWidth + 1`
- `document.body.scrollWidth <= window.innerWidth + 1`
- 主要按钮可点且没有文字压出按钮。
- 打开移动菜单后不遮挡后续内容到不可恢复。
- 需要横向滚动的表格或导航只在自己的容器内滚动。

桌面回归验收：

- `1440x900` 下抽查 `/`、`/drink`、`/calendar`、`/report`、`/dashboard/status`。
- 桌面 tab strip、补给站资产 chip、场景背景和主要网格保持当前展示。
- `git diff` 中 PC 默认 CSS 不应出现视觉规则改动；新增 CSS 应位于手机媒体查询内。

## 风险与处理

- CSS 历史规则较多，后写规则可能覆盖早期修复。处理方式是把本轮规则集中放在末尾，并用测试锁定关键移动端契约。
- 某些组件只有 Tailwind class，没有稳定 CSS hook。处理方式是添加不影响样式的 class hook，再在手机断点内写 CSS。
- 补给站 UI Lab 页面有多个 `min-width` 和 `100vw`。处理方式是优先修生产嵌入态和内容容器，不改静态原型桌面展示。
- PC 不变是硬约束。任何默认样式或 `min-width` 以上样式改动都需要从计划中移除，除非只是新增 class hook 且没有样式效果。

## 验收标准

- 所有新增和扩展的 CSS/组件测试通过。
- `npm run lint` 通过。
- `npm run build` 通过。
- 指定手机视口没有页面级横向滚动。
- 指定桌面视口没有可见 UI 展示变化。
- 最终 diff 只包含移动端 CSS、移动端测试和必要 class hook。
